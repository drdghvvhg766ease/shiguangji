# 时光迹功能需求确认

日期：2026-10-01。来源：本轮逐项问答。

本文记录已确认的需求和实现默认值。本轮已完成圈子角色与入圈审核、资料设置、消息公告、点赞回复及分类收藏；具体验证见同日工作记录。多分支记录与分册关联仍按用户要求暂缓。

## 总体约定

- 五个模块均纳入完善范围：圈子管理、生活时间线、个人主页、照片与发布、管理后台。
- 后续未逐项确认的同类功能和交互默认参照微信，不再逐项追问。
- 用户已经明确的规则优先于微信默认行为和历史文档。
- 圈子、分册、分支时间线等时光迹特有功能按项目约定实现。微信没有直接对应的能力时，根据现有结构采用一致的交互方式。
- 圈子生活痕迹线展示成员共享的生活记录；个人主页痕迹线记录本人对参加圈子的操作，按实际操作时间排序。

## 圈子与成员

| 事项 | 用户确认的规则 |
| --- | --- |
| 角色 | 圈主、管理员、普通成员 |
| 管理员任免 | 仅圈主可以任命和撤销 |
| 内容管理 | 管理员可以删除其他成员发布的圈内记录 |
| 成员管理 | 管理员可以移出普通成员 |
| 入圈审核 | 使用邀请码申请加入，需要圈主或管理员审核；通过后才能访问圈内内容 |
| 成员邀请 | 普通成员可以邀请朋友，受邀者仍需审核 |
| 分册与分支创建 | 普通成员可以创建 |
| 普通成员管理范围 | 只能编辑、删除自己创建的分册和时间线分支 |
| 圈主与管理员管理范围 | 可以编辑、删除圈内所有分册和时间线分支 |
| 退出或移出后的记录 | 原有生活记录继续保留在圈子中 |
| 新成员历史访问 | 审核通过后，可以查看加入之前的全部圈内记录 |
| 解散圈子 | 仅圈主可以操作 |

角色边界按上述规则执行：移出普通成员的权限不扩展为移出圈主或其他管理员；删除他人记录的权限不扩展为修改他人正文。记录作者的编辑能力继续保留。

## 个人主页与消息

| 事项 | 用户确认的规则 |
| --- | --- |
| 个人资料 | 可以修改头像和昵称 |
| 修改密码 | 提供修改密码功能，并验证当前密码 |
| 站内消息中心 | 接收入圈审核结果、评论回复和圈子通知 |
| 圈子公告 | 圈主和管理员可以发布，并通知圈内所有成员 |
| 我的收藏 | 可以收藏圈内照片和生活记录 |
| 收藏分类 | 支持创建多个收藏夹分类 |
| 收藏夹可见性 | 由收藏夹所有者自己设置 |

收藏夹的可见范围选项未逐项确认，按本轮总体约定采用默认私密、可选择面向指定圈子分享的项目默认值。收藏和分享继续检查原记录的圈子访问权限；收藏夹可见性不能扩大原记录的访问范围。退出圈子或原记录删除后，收藏不保留可访问的媒体副本。

## 暂缓的时间线需求

用户已确认以下目标，随后明确表示这些以后再完善，本轮先收集其他功能需求：

- 同一条生活记录可以同时归入多个时间线分支。
- 同一本分册可以同时关联多个时间线分支。

记录加入分册后是否自动进入该分册所有分支的提问，用户未单独回答；该规则随上述需求后续完善，不能标记为已确认或已实现。

## 后续默认交互

以下是根据“剩下的功能问题都和微信一致”采用的实现默认值，区别于前文逐项确认事项：

- 头像预览和裁剪、资料保存、消息未读提示及已读处理，采用微信同类操作习惯。
- 记录互动提供点赞、取消点赞、评论、回复及相应消息反馈；可见范围按本项目圈子成员权限执行。
- 照片查看、前后切换、触控手势、返回原位置、发布草稿和上传反馈采用熟悉的移动端交互。
- 搜索、筛选、加载、空状态和失败重试沿用现有界面规范；危险操作保留确认和失败后的上下文。
- 外观继续沿用用户已选定的艺术影集方向；微信参照用于功能行为和操作习惯。
- 管理后台沿用项目审核、权限和留存规则，其对应操作采用一致反馈。

## 实施顺序

1. 圈主、管理员与普通成员权限，以及邀请和入圈审核。
2. 头像昵称、修改密码、站内消息与圈子公告。
3. 收藏夹分类和可见范围，以及照片发布和互动。
4. 管理后台对应功能、权限与跨页面流程验证。
5. 后续完善多分支记录、分册关联和时间线继承关系。

实施顺序为依据本轮问答形成的工程安排。第 1–4 项已实现并验证；第 5 项留待后续，不改变当前每条记录、每本分册关联一条分支的规则。
